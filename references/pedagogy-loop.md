# 四模式

四种模式是产品，不是四个按钮。切模式时：清舞台、藏答案卡、`runToken++`、停掉旧教学。

## 自由探索 `explore`

学生先动手。控件是**本族主变量**。

| 族 | 主控件 | 学生在凑什么 |
|---|---|---|
| 计数 | 两种东西的 +/-（点按 + 长按加速） | 头数和脚数同时命中 |
| 匀速 | 时间轴（可拖、可点刻度） | 两支一样高 / 两人相遇 / 水齐 |
| 条形 | 拖各段长度 | 和或差等于题面 |
| 离散 | 点的个数 / 段数 | 点数或间隔命中 |

命中目标：主计量变绿，庆祝，出示答案卡，阿临用一句话说出规律，不泄下一法的全部推导。
未命中：轻反馈（「甲还高着一截」「头数对了，脚少了」），不要弹窗。

## 跟我学 `teach`

控件锁住，学生按「下一步」走。方法页签只在这个模式出现。

每一步的形状：

1. 阿临先用一句话说将要发生的事。
2. 按钮文案是悬念，不是「下一步」。
3. 点下去：舞台动（可 await 分步）。
4. 动完再讲这步的数学。
5. 最后一步出示答案卡 + 庆祝，按钮藏起。

至少两种方法。切换方法：`runToken++`，舞台清零，从该方法第 0 步重来。

教学流程必须是 `async` 且每一步开头记下 `const myToken = runToken`，每次 `await` 之后 `if (myToken !== runToken) return`。

## 闯关 `challenge`

同一结构，新数字。题面改成新的已知量。学生用探索那套控件去凑。

生成算法：**答案先行**。

```text
计数：抽 countA、countB → heads、feet
匀速（等高）：抽 tStar、rateA、rateB、remain
         → heightA = remain + rateA*tStar
         → burnA   = heightA / rateA
```

保证整数（或一位小数以内）。把 `state.challenge = { …, solve: solveFor(...) }` 存下来，命中判定用 challenge，不用默认 PROBLEM。

## 出题 `create`

藏探索控件，出示滑杆。每滑一次：更新预览题面、更新舞台、用当前值跑 `solveFor`。无解就老实说。
给「复制分享链接」，query 只放已知量（匀速：`h1 t1 h2 t2`；计数：`a b` 其实会泄答案——计数族可以只放 heads/feet）。收到链接进闯关，不要进探索默认题。
